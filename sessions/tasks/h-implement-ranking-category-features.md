# 排序模型类别特征优化

## Problem/Goal

当前12类别（new_categories）只用于召回阶段，没有作为排序特征进入LightGBM Ranker模型。同时存在以下问题：

1. **12类别特征缺失**：Ranker模型没有使用类别重叠等特征，无法学习类别相关性
2. **正样本率极低（0.07%）**：2,864,988个训练样本中只有2,001个正样本，可能导致模型偏向预测负类
3. **12cat召回权重过低（0.01）**：category渠道的自动学习权重太低，12cat召回的候选难以进入最终结果

## Success Criteria
- [ ] 添加类别特征到Ranker：category_overlap（类别重叠数）、category_match（是否有匹配）
- [ ] 实现负样本下采样，将正负样本比例调整到1:100以内
- [ ] 增加12cat召回基础权重到0.8（与vector召回相当）
- [ ] 重新训练模型后，类别特征进入特征重要性Top 15
- [ ] API推荐结果中12cat召回占比提升到>10%

## Context Manifest

### How This Currently Works: LightGBM Ranker Training Pipeline

#### Overview of the Recommendation System Architecture

The recommendation system follows a multi-stage pipeline: Recall -> Score Fusion -> Personalization -> Ranking -> Quality Filtering -> MMR Reranking -> Exploration. The Ranking stage uses a LightGBM LambdaRank model to score candidates.

**Training Data Flow:**
1. `pipeline/aggregate_matomo_events.py` collects user events (exposures, clicks, conversions)
2. `pipeline/build_training_labels.py` joins exposures with clicks to create training samples
3. `pipeline/train_models.py` loads samples and trains the LightGBM Ranker

#### Training Samples Generation (`pipeline/build_training_labels.py`)

The training samples are generated by joining **exposure** events with **click** events. The key logic is in `build_training_labels()`:

```python
# From build_training_labels.py Line 159-167
samples = exposures.copy()
samples = samples.merge(
    clicks[["request_id", "dataset_id", "server_time"]],
    on=["request_id", "dataset_id"],
    how="left",
)
samples = samples.rename(columns={"server_time": "clicked_at"})
samples["label"] = samples["clicked_at"].notna().astype(int)  # Binary: 1=clicked, 0=not clicked
```

**Training Samples Schema** (`data/processed/ranking_training_samples.parquet`):
- `request_id`: Unique request identifier (used for LambdaRank grouping)
- `page_id`: **The target item's dataset_id** (the page user was viewing when recommendations were shown)
- `dataset_id`: Candidate item's dataset_id
- `position`: Position in recommendation list (1-indexed)
- `label`: Binary click label (1=clicked, 0=not clicked)
- `score`: Recall score from the recommendation engine
- `reason`: Recall channel that produced the candidate (e.g., "behavior", "content", "12cat")
- `channel`: Extracted primary channel from reason
- `channel_weight`: Weight applied to the channel

**Current Problem - Extremely Low Positive Rate:**
The training log shows only ~2,001 positive samples out of ~2,864,988 total samples (0.07% positive rate). This severe class imbalance causes the model to be biased toward predicting negative.

**Problem: 12cat weight is too low**
The current `channel_weights.json` shows:
```json

  ...

```
There is no learned weight for "12cat" channel specifically. The hardcoded `0.5` multiplier in the code is applied to normalized scores, but then when computing `channel_weight` for ranking, it falls back to `DEFAULT_CHANNEL_WEIGHTS.get(channel, 0.1)` which returns 0.1 for unknown channels like "12cat".

#### 2. Implement Negative Sample Downsampling

**Location:** `/root/recommendation-system/pipeline/train_models.py` after loading `ranking_samples` (Line 1863-1878)

**Current positive rate:** 0.07% (2,001 positives / 2,864,988 total)
**Target positive rate:** ~1% (1:100 ratio)

**Implementation approach:**
```python
# After loading ranking_samples
if not ranking_samples.empty:
    positive_samples = ranking_samples[ranking_samples["label"] == 1]
    negative_samples = ranking_samples[ranking_samples["label"] == 0]

    # Target ratio: 1:100 (1% positive rate)
    target_negative_count = len(positive_samples) * 100

    if len(negative_samples) > target_negative_count:
        # Downsample negatives
        negative_samples = negative_samples.sample(n=target_negative_count, random_state=42)
        ranking_samples = pd.concat([positive_samples, negative_samples], ignore_index=True)
        LOGGER.info(
            "Downsampled negatives: %d -> %d (positive ratio: %.2f%%)",
            len(negative_samples), target_negative_count,
            100 * len(positive_samples) / len(ranking_samples)
        )
```

**Important considerations:**
- Should downsample BEFORE train/val split to maintain consistent ratios
- Consider using stratified sampling by request_id to preserve group structure for LambdaRank
- Add environment variable to configure target ratio: `RANKING_DOWNSAMPLE_RATIO=100`
