## 二、发现并修复的两个缺陷

### 缺陷 1（严重）：`/similar` 每次都抛 `NameError` → 全部降级成"热销兜底"

- **现象**：`app/main.py` 中 `get_similar` 有一段重复粘贴的代码块，第一份日志里引用了**该函数作用域不存在的 `user_id`**：
  ```
  ERROR Error in get_similar (dataset=16307, ...): name 'user_id' is not defined
  ```
- **后果**：每一次 `/similar` 请求都抛异常 → 被兜底逻辑接住 → 返回 `fallback:popular`（全局热销榜）。**如果直接上生产，"看了又看"会从"偶尔不相关"变成"每次都推热销低价品"，比现在更差。**
- **定位方式**：`python -m pyflakes app/main.py` 精确指出 `app/main.py:3684: undefined name 'user_id'`。
- **修复**：删除重复代码块与越界引用，保留使用 `None` 的那份日志（`/similar` 接口本就没有用户上下文）。
- **教训**：此前只做了静态自检（60 项断言）+ `py_compile`，都发现不了这类作用域错误。**验证必须包含"真实起服务 + 打一次 HTTP 请求"**，并把 `pyflakes` 纳入提交前检查。

### 缺陷 2（中等）：配额放行顺序错误 → 热门条数突破上限

- **现象**：候选不足时按原排名顺序放行被挡下的候选项，而排名靠前的恰恰是低价热销品，于是"刚被配额挡下的鼠标指针又被填回来"：
  ```
  List quota applied: blocked=27, selected=12, popular_in_result=4   ← 超过 max_popular=3
  ```
- **修复**：放行时**优先放行非热门来源**（内容/语义/标签/价格/行为），热门来源排到最后。
- **复测结果**：`popular_in_result=3` ✅，日志显示放行的 3 条全部为"非热门来源"，其中一条正是高度相关的 16305。

## 五、本地测试环境（可复现，全程不影响生产）

### 5.1 环境隔离设计

| 项目 | 做法 | 原因 |
|------|------|------|
| 浏览器/DB | 独立容器 `reco-redis`（端口 16379） | 绝不连生产 Redis |
| 服务端口 | `localhost:18090` | 与生产 8090 区分 |
| Sentry | `SENTRY_DSN=`（置空） | 避免污染生产告警 |
| 数据 | `models/`、`data/` 从服务器**复制**到本地后只读挂载 | 不改动生产文件 |
| 代码 | `app/`、`config/`、`pipeline/` 挂载进容器 | 改代码后重启容器即可，无需重新构建 |

### 5.2 从 0 搭建步骤

```bash
# ① 镜像：瘦身版（剔除 torch/faiss/transformers/mlflow，673MB，约 2 分钟构建完）
cd ~/python/recommendation-system
docker build -f Dockerfile.local -t reco-local:latest .

# ② 独立 Redis
docker network create reco-net 2>/dev/null
docker run -d --name reco-redis --network reco-net -p 16379:6379 redis:7-alpine

# ③ 数据（详见 docs/本地测试数据清单 或本报告附录）
#    models/                      ← 服务器 /root/recommendation-system/models/（整目录，244MB）
#    data/processed/*.parquet     ← 服务器同目录下 6 个文件（约 195MB）

# ④ 起服务
docker run -d --name reco-local --network reco-net -p 18090:8000 \
  -v "$PWD/app:/app/app" -v "$PWD/config:/app/config" -v "$PWD/pipeline:/app/pipeline" \
  -v "$PWD/models:/app/models" -v "$PWD/data:/app/data" -v "$PWD/logs:/app/logs" \
  --env-file .env.local reco-local:latest

# ⑤ 验证（约 90 秒后模型加载完成）
curl -s localhost:18090/health
curl -s "localhost:18090/similar/16307?limit=12" | python3 -m json.tool | head -40
```

### 5.3 踩坑记录（重要）

1. **响应缓存 300 秒**：`/similar` 结果缓存在 Redis DB0（key `similar:{id}:{limit}`）。**改完代码复测前必须清缓存**，否则拿到的是旧结果：
   ```bash
   docker exec reco-redis redis-cli -n 0 flushdb    # 只清 DB0，DB1 特征库不要动
   ```
2. **不要用 `docker compose up`**：`docker-compose.yml` 的服务 `env_file` 写死了 `.env` / `.env.memory` / `.env.prod`，本地没有这些文件会直接报错；且会连带拉起 Airflow/Postgres/Prometheus 等一堆不需要的服务。本地用 `docker run`。
3. **改代码后要重启容器**：容器 CMD 没有 `--reload`，挂载生效但不自动重载：`docker restart reco-local`（重启后约 90 秒加载完模型）。
4. **提交前跑一次静态检查**（能发现作用域类错误）：
   ```bash
   python -m pyflakes app/main.py
   ```
